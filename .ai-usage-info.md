# AI Usage Info

## Sinn der Library

`brace/mod-spaserve` bindet eine Vite-basierte Single-Page-App an Brace an. Im Development-Modus läuft Vite vor Brace und übernimmt TypeScript, CSS und HMR; Brace liefert API-Routen und die SPA-Shell. In Production liefert Brace die von Vite gebauten Assets aus.

Für neue Integrationen sind insbesondere diese Bausteine vorgesehen:

- `SpaStaticFileServerMw` für SPA-Shell und Production-Assets
- `ViteAutoHtml` für Development-/Production-HTML
- `TypeScriptApiStubModule` für den typisierten TypeScript-API-Stub

## Beispiele

Die vollständige Konfiguration liegt unter `examples/demo`:

- `examples/demo/middleware.php` — Brace-Routen, `TypeScriptApiStubModule`, Development-Erkennung und SPA-Middleware
- `examples/demo/vite.config.ts` — Vite-Proxy und automatische Stub-Generierung mit `vite-plugin-run`
- `examples/demo/package.json` — benötigte Frontend-Abhängigkeiten
- `examples/demo/src/main.ts` — Verwendung des generierten `API`-Clients

Die README enthält zusätzlich die zusammenhängende Beschreibung: `README.md`.

## Start-HTML

`ViteAutoHtml::$startHtml` enthält vertrauenswürdiges Anwendungs-HTML und wird unverändert am Anfang des `<body>` vor den automatisch erzeugten Script-Tags ausgegeben. Vollständig verschachtelte Startstrukturen können direkt angegeben werden:

```php
new ViteAutoHtml(
    development: true,
    startHtml: '<app-shell><router-content></router-content></app-shell>',
);
```

Kein nicht vertrauenswürdiger oder vom Benutzer übernommener Inhalt darf in `startHtml` interpoliert werden.

## TypeScript-API-Stub konfigurieren

Der Stub-Generator wird direkt als Brace-Modul konfiguriert. Der Zielpfad wird genau dort angegeben; zusätzliche Dateien wie `api-stub.php` oder `build-api.php` sind nicht vorgesehen.

```php
use Brace\SpaServe\Codegen\TypeScriptApiStubModule;

$callback = [UserController::class, 'get'];
$app->router->on('GET@/api/users/:userId', $callback);

$api = new TypeScriptApiStubModule(
    targetFile: __DIR__ . '/frontend/src/generated-api.ts',
    autoGenerateInDevelopment: true,
);

$api->route(
    name: 'User.Get',
    path: '/api/users/{userId}',
    methods: 'GET',
    callback: $callback,
);

$app->addModule($api);
```

`route()` beschreibt den Client-Vertrag, registriert aber nicht die HTTP-Route. Die tatsächliche Brace-Route und der Stub-Vertrag verwenden deshalb denselben Callback.

## Development-Autogeneration

Mit `autoGenerateInDevelopment: true` erzeugt das Modul den Stub beim normalen Brace-Bootstrap ausschließlich in `EnvironmentType::DEVELOPMENT`.

Mit

```php
autoGenerateInDevelopment: false
```

wird diese automatische Generierung abgeschaltet.

CLI-Aufrufe lösen die Development-Autogeneration nicht bereits beim Bootstrap aus. Dadurch wird bei einem expliziten Build nur der registrierte Build-Command ausgeführt.

## Brace Command

`TypeScriptApiStubModule` registriert selbst den Application-Command `spa-api-build` und stellt Brace Command bei Bedarf bereit. Es ist kein separates CLI-Modul für die Stub-Generierung notwendig.

Explizite Generierung:

```bash
vendor/bin/brace spa-api-build
```

Der Command schreibt in den am Modul konfigurierten `targetFile`.

Der `GeneratedFileWriter` ersetzt die Datei nur, wenn sich der generierte Inhalt tatsächlich geändert hat. Wiederholte Generierung ohne API-Änderung darf deshalb keinen unnötigen Vite-HMR- oder Reload-Zyklus auslösen.

## Vite

Für Vite keinen projektspezifischen Brace-Plugin-Code schreiben. Die Demo verwendet das generische `vite-plugin-run`, um den registrierten Brace-Command beim Vite-Start und vor dem Production-Build auszuführen.

Siehe:

- `examples/demo/vite.config.ts`
- `examples/demo/package.json`

Der einzige projektspezifische Wert auf Vite-Seite ist der Pfad zu `vendor/bin/brace`, falls das Frontend in einem Unterverzeichnis liegt. Der Pfad zur generierten TypeScript-Datei bleibt ausschließlich im `TypeScriptApiStubModule` konfiguriert.

## Hinweise für AI-Agenten

Bei einer Integration dieses Pakets:

- keine separate PHP-Datei nur für Stub-Konfiguration oder Stub-Build anlegen
- kein eigenes Brace-CLI-Modul für die Stub-Generierung anlegen
- keinen eigenen Vite-Plugin-Hook schreiben, wenn `vite-plugin-run` ausreicht
- den Ausgabeort über `TypeScriptApiStubModule::$targetFile` konfigurieren
- den vom Modul registrierten Command `spa-api-build` verwenden
- für vollständige, aktuelle Konfiguration zuerst die Dateien unter `examples/demo` prüfen
